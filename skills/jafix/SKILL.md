# jafix

日本語の文書を書いた・編集した後に、jafixで今回の編集だけを校正する手順です。
修正ルールの箇所は `jafix fix` で直し、残った指摘ルールの指摘は手で書き直します。
校正を頼まれていなくても、日本語の文書を編集したら作業の最後にこの手順を実行します。

## 1. jafixがあるかを確かめる

```sh
jafix --version
```

コマンドが見つからないときは、自分でインストールしません。jafixが無いことを、導入手順のURL `https://github.com/mjun0812/jafix#導入` を添えて利用者へ伝え、この手順を終えます。

## 2. 対象のファイルを決める

対象は、今回の作業で書いた・編集した日本語の文書(Markdownとテキストファイル)だけです。
`jafix check` と `jafix fix` には、必ずそのファイルのパスを渡します。
パスを付けない `--diff` は、今回編集していないファイルの変更まで対象にするので使いません。

次のファイルは渡しません。jafixは拡張子を問わずMarkdownの構文で本文を判定するので、渡すとソースコードにも修正ルールが当たります。

- ソースコードと設定ファイル
- バイナリ
- 導入したskillのファイルなど、今回編集していないファイル

## 3. 既存のファイルと新規のファイルに分ける

`--diff` は、Gitの `HEAD` からの差分で追加・変更した行(対象行)だけを扱います。
未追跡のファイルは `--diff` の対象にならず、何も出さずに終了コード0を返します。
新規のファイルを確認済みと取り違えないように、先にファイルを分けます。

```sh
git rev-parse --verify HEAD
```

- 失敗した場合: Gitリポジトリの外か、最初のコミットより前のrepositoryです。`--diff` は終了コード2になるので、対象のファイルをすべて「新規」として扱います
- 成功した場合: 次のコマンドに出たファイルを「新規」、出なかったファイルを「既存」とします

```sh
git ls-files --others --exclude-standard -- <対象のファイル>...
```

新規のファイルは全行が今回の編集なので、`--diff` を付けずにファイルを指定して全行を対象にします。
`git add` で未追跡のファイルを差分に入れることはしません。利用者のステージの状態が変わるからです。

## 4. 自動修正する

修正ルールの箇所を、先に `jafix fix` で直します。

```sh
jafix fix --diff <既存のファイル>...
jafix fix <新規のファイル>...
```

`fix` は指摘が残っても終了コード0を返します。結果は次の `check` で確かめます。

## 5. チェックする

```sh
jafix check --diff <既存のファイル>...
jafix check <新規のファイル>...
```

指摘は1件1行で、`パス:行:列: [ルールID] 文面` の形で出ます。

| 終了コード | 意味                                                   |
| ---------- | ------------------------------------------------------ |
| 0          | 修正ルールに当たる箇所も指摘も無い                     |
| 1          | 修正ルールに当たる箇所か指摘が1件以上ある              |
| 2          | 対象の指定、ファイルの読み込み、設定ファイルに問題がある |

終了コード2のときは、出力を読んでパスや `--diff` の使い方を直します。設定ファイルが不正なときは、自分で直さずに利用者へ伝えます。

## 6. 残った指摘を手で直す

指摘ルールの指摘は、`jafix fix` では直りません。指摘された箇所を読み、文意を保ったまま書き直します。
対象行ではない既存の行は書き換えません。

誤検知と判断した指摘は直さずに残し、どの指摘をなぜ残したかを利用者へ報告します。

## 7. 指摘が無くなるまで繰り返す

書き直したら、5と同じ `check` を再実行します。修正ルールの箇所が出たら、4の `fix` で直します。
終了コード0になるか、残した指摘をすべて誤検知として説明できるまで繰り返します。

## プロジェクト設定

jafixは、対象ファイルに最も近い `.jafix.toml` (プロジェクト設定)と共通設定を自動で読みます。使うルールはこれらの設定で決まるので、オプションでルールを指定しません。

指摘を消す目的で、設定ファイルを変更したり、指摘を外すコメントを足したりしません。どちらも利用者に頼まれたときだけ行います。

## hookとMCP

hookを登録している環境では、編集の直後にhookが対象行を自動修正し、残った指摘をagentへ返します。作業の最後には、この手順で確かめます。
hookとMCPの登録は、次のドキュメントにあります。

- [hookへの登録](https://github.com/mjun0812/jafix/blob/main/docs/hooks.md)
- [MCPの登録](https://github.com/mjun0812/jafix/blob/main/docs/quick-start.md#mcp)
