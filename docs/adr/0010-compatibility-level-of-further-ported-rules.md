# ADR-0010: 追加で移植するルールは、判定の条件をtextlintから写し、不具合に近い挙動は写さない

`textlint-rule-preset-ja-technical-writing` の23ルールの後に移植するルールは、判定の条件(何を指摘するかと、その例外や辞書)をtextlintから写し、textlintの不具合に近い挙動は写さない。形態素解析を使うかどうかは問わない。ADR-0006が形態素解析を使う11ルールに決めた扱いを、追加で移植するルールのすべてに当てる。23ルールの扱いは、ADR-0006のまま変えない。

利用者は、textlintと1件も違わないことを目標にせず、ルールの目的が果たせればよいと決めている。癖まで写すと、本文でない箇所への指摘や、文書の構造をまたいだ誤った一致まで残る。たとえば、ai-writingのpresetは、リスト項目の原文に正規表現を当てるので、インラインコードの中の絵文字も指摘する。また、ai-words-jaのpresetは、一致の途中の状態を本文の範囲をまたいで持ち越すので、段落の境目の `腑に` と `落ちる` を1語として指摘する。

変える点は、移植するspecごとに列挙する。ai-writingとai-words-jaの7ルールでは、次の点を変えた。

- インラインコードの中身とHTMLのタグを判定に入れない。太字の中にインラインコードがあっても、太字には当てる
- リスト項目の中の段落だけを見る。項目の中のコードブロックやHTMLのブロックには当てない
- `ai-tech-writing-guideline` は、インラインコードを同じ文字数の空白に置き換えてから当てるので、コードを挟んだ語はつながらない
- `no-ai-colon-continuation` は、コロンの前の空白を除いてから、最後のトークンが名詞かを見る
- `no-ai-words` は、一致の途中の状態を本文の範囲をまたいで持ち越さず、すべての位置から当てる。利用者の辞書で、jafixのトークンに無い項目と知らない項目名は、設定の誤りにする
- `no-short-topic-comma` は、`true` で有効になる。長さをUTF-16の単位ではなく文字で数える

期待値は、実物のtextlintの実行結果から作る。形態素解析を使うルールは、kuromojiとlinderaのトークンが同じ入力の結果を使う。textlintと変える箇所の期待値は、上の規則から個別に決める。

## Considered Options

- ADR-0005のように、癖を含めてtextlintと同じ箇所を指摘する。本文でない箇所への指摘も残る

## Consequences

- 追加で移植するルールの指摘は、同じ文書でもtextlintと変わりうる。違いは、解析器の違いか、specで列挙した変える点のどちらかで説明できる
- textlintのpresetかルールのversionが上がったら、fixtureの期待値を作り直して比べる
