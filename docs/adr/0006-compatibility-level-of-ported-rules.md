# ADR-0006: 移植したルールは判定の条件をtextlintから写し、形態素解析を使うルールは同じ結果を目標にしない

textlintの `preset-ja-technical-writing` から移植した23の組み込みのルールは、判定の条件(どの箇所を指摘するか、例外、辞書)をtextlintから写す。textlintと同じ結果にする度合いは、形態素解析を使うかどうかで分ける。ADR-0005は、移植したルールのすべてに同じ箇所の指摘を求めていたので、このADRで置き換える。

形態素解析を使わない12ルールは、ADR-0005の内容をそのまま引き継ぐ。同じ入力に対して、textlintと同じ箇所を指摘し、見逃しや、許可リストが直後の文字まで許すような癖も写す。期待値は、textlint 15.8.0とpreset 12.0.2の実行結果から作る。textlintと変えるのは、次の点だけである。

- textlintが誤った位置を出す3か所は、正しい位置に出す。`sentence-length` は文の先頭、`max-comma` はその文の最後のカンマ、`ja-no-mixed-period` は末尾の文字である
- 例外では止まらない
- 本文ではない箇所(裸のURL、省略形の参照リンクの文字列、画像)には、本文の範囲ごとに当てるルールを当てない
- 列は文字で数える

形態素解析を使う11ルールは、textlintと同じ結果にすることを目標にしない。jafixはlindera、textlintはkuromojiで解析する。同じIPADICでも品詞の変わる文があるので、不具合に近い挙動まで写しても同じ結果にはならない。ルールの目的を果たすことを優先し、次の点をtextlintと変える。

- トークンは、linderaの結果を使う
- 位置は、指摘する語の元のソースでの位置にする。textlintは、絵文字などの後ろや、段落の2文目以降で位置がずれる
- 語の並びを当てる状態を、本文の範囲、文、段落、ファイルをまたいで持ち越さない。並びは、すべての位置から当てる
- 文の単位のルールは、インラインコードの中身、リンクの宛先、リンクや強調の記号を判定に入れない。文の区切り方は、12ルールと同じにする
- 例外では止まらない

11ルールの期待値は、textlintの実行結果のうち、kuromojiとlinderaのトークンが同じ入力のものを使う。textlintと変える箇所の期待値は、上の規則から個別に決める。

## Considered Options

- 11ルールも、癖を含めてtextlintと同じ箇所を指摘する。kuromojiの解析の手順をRustに書き直してkuromojiの辞書を使えば、トークンは一致する。試作では、約25万行でkuromojiと全項目が一致した。ただし、binaryが約64MBになり、自前の解析器と17MBの辞書を持ち続けることになる。利用者は、textlintとの一致ではなく、ルールの目的を果たすことを選んだ
- 12ルールも、不具合に近い挙動を写さない。textlintの実行結果と比べて確かめられる範囲が狭くなる(ADR-0005で退けた案)

## Consequences

- 11ルールの指摘は、同じ文書でもtextlintと変わりうる。違いは、解析器の違いか、上に挙げた変える点のどちらかで説明できる
- textlintのpresetかルールのversionが上がったら、fixtureの期待値を作り直して比べる
- jafixとtextlintは、Markdownの解析器が違う。fixtureに無い入力では、nodeの分け方の違いで指摘の有無の変わることがある
