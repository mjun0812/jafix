# ADR-0017: 利用者の置き換えの結果を、辞書で別の語を求める組み込みの指摘ルールが指摘するなら、設定の誤りにする

利用者の置き換え(`prh` の辞書、`@textlint-rule/pattern` の `replace`、`terminology` の `terms`)の固定の部分を、辞書で語を別の書き方にするよう求める有効な組み込みの指摘ルールが指摘するとき、設定の読み込みで不正にする。理由には、2つのルールのIDと、どちらかを無効にする書き方を書く。この決定は、組み込みの修正ルールと逆の書き方を求めるルールを断るADR-0008を、利用者の置き換えと辞書の指摘ルールの組に広げるものである。2026-11-16に、利用者がこの扱いを選んだ。

この組は、ADR-0008が断る修正ルールの組と同じ往復を起こす。たとえば、`サーバー` を `サーバ` にする `prh` の辞書と `2.1.6.カタカナの長音` を有効にすると、hookが直した `サーバ` を `2.1.6` が指摘する。agentが指摘に従って `サーバー` に戻すと、次の編集でhookがまた `サーバ` に直す。辞書の指摘ルールは特定の語を特定の書き方にするよう求めるので、両方を満たすには、その語を使わない以外の書き方が無い。

判定に入る指摘ルールは、辞書で語を置き換えるよう求める13ルールである。`preset-jtf-style` の辞書の4ルール(`2.1.5` の辞書の部分・`2.1.6`・`2.2.1`・`2.2.3`)、ひらがな系の5ルール、`ja-no-abusage`、`@textlint-ja/no-synonyms`、`terminology` の組み込みの辞書、`common-misspellings` がそれにあたる。`@textlint-ja/no-synonyms` は、`preferWords` の語にするよう求めるときだけ判定に入れる。`preferWords` が無ければ、表記の揺れを指摘するだけで、文書のほかの表記を揃えれば両方を満たせるためである。記号の種類を求めるルール(`4.2.7`・`4.3.1` など)、`spelling` の候補、さ入れ・さ抜きの文法の規則、文の単位で表現を言い換えさせる `ja-no-redundant-expression` は、ADR-0008の指摘ルール同士と同じく、別の書き方で両方を満たせるので入れない。

判定は、固定の部分を、段落の直下にある本文の範囲1つだけの文書とみなし、参照に接する端の指摘を除いて行う。ADR-0008の後に作った、組み込みの修正ルールと逆の置き換えの判定(`reject_opposite_replacements`)と同じ固定の部分を使い、同じ箇所で理由を作る。そのため、形態素解析の品詞や前後の語で決まる指摘は、判定できないことがある。`お願い致します` は `ja-hiragana-hojodoushi` が指摘するので不正になるが、`致します` だけでは `致し` が補助動詞と決まらないので、指摘が出ず、不正にしない。判定できない組は、設定の誤りにせず、READMEで往復が起きうることを伝える。文脈を推し量ってエラーにすると、正しい設定まで読み込めなくなるためである。

2026-11-16に、捕捉参照に隣接する端を文書の先頭や末尾として扱う判定を改めた。固定の部分ごとに前後の参照の有無を保持し、参照に接する端まで広がる指摘は、設定の不正にしない。たとえば `expected: サーバ$1` と `pattern: /サーバー(ラック)/` の固定の部分 `サーバ` を単独で当てると、`2.1.6` が文末として指摘する。しかし、実際の置き換え後の `サーバラック` は指摘しない。固定の部分の内側で完結する指摘は引き続き判定に入れる。参照の値を推測しないため、この扱いで読み込める設定も、参照の内容次第で往復することがある。修正ルール側の扱いはADR-0008に記す。

固定の部分は数千になりうる(公開の最大の `prh` の辞書は約1,300ルールである)。hookは編集のたびに設定を読むので、固定の部分を改行でつないだ文字列に辞書を当て、指摘と重なる部分だけを1つずつ当て直す。形態素解析は、トークンの並びの表層の先頭の文字を含む部分だけに行う。

## Considered Options

- 今のまま、設定の不正にせず、READMEで往復が起きうることを伝える。利用者は、往復が起きてから気付くことになる
- hookやfixの実行時に、置き換えの結果を指摘ルールが指摘する箇所を直さない。往復は止まる。代わりに、指摘ルールを有効にしただけで、利用者の書いた置き換えが、理由を示されないまま当たらなくなる
- すべての指摘ルールを判定に入れる。記号のルールや `spelling` のように、別の書き方で両方を満たせる組まで断ることになる

## Consequences

- 辞書の指摘ルールを足すspecは、そのルールを判定に入れるかを決める。入れるなら、`DICTIONARY_REPORT_RULES` に足す
- 判定のために、設定の読み込みで辞書の正規表現と形態素解析を利用者の置き換えに当てるので、`prh` の辞書が大きいほど、hookの時間が延びる
- 文脈で決まる指摘と置き換えの組では、設定を読み込めても同じ箇所の修正が繰り返されることもある。READMEには、その組の例とどちらかを無効にする書き方を示す
