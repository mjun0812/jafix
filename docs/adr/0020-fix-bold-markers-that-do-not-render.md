# ADR-0020: 太字にならない `**` の組は、記号を動かす・空白を足す置き換えでも修正ルールにする

`yomiyasu-bold-not-rendered` を、指摘ルールから修正ルールに変える。太字として表示されず `**` が文字のまま残る組を、yomiyasu 3.4.1の3通りの直し方で直す。かっこの内側だけを太字にする直し方(`**「重要」**` を `「**重要**」` へ)、句読点を太字の外に出す直し方(`**重要。**次` を `**重要**。次` へ)、内側の端の空白を削除して外側に空白を入れる直し方(`**注意：**ここ` を `**注意：** ここ` へ)である。2026-11-27に、利用者がこの3通りをすべて自動で直すと決めた。

この修正は、ADR-0009の例外である。ADR-0009は、修正ルールにする置き換えを、字種だけを変えるもの・空白の削除・利用者が書いた置き換えの3種類に限り、空白や記号を足す置き換えを指摘ルールにすると決めた。太字の修正は、記号の位置を動かし、空白を足す。

例外にするのは、書き手の意図がはっきりしていて、直した結果を確かめられるからである。`**` の組が文字のまま残る箇所では、書き手は太字にするつもりで書いている。ADR-0009が記号を足す置き換えを指摘にした理由は、文書ごとの表記の方針に関わることだった。太字にならない記号を残す方針の文書は、考えにくい。

直すのは、直した後の結果を確かめられた組だけにする。候補を当てた後の2つの `**` が、GFMの規則とCommonMarkの規則の両方で、太字の始まりと終わりになることを確かめる。さらに、組のあるブロックを解析し直し、その組だけが太字に増えて、ほかの強調・太字・リンク・インラインコード・画像が変わらないことを確かめる。確かめられない組は、今までどおり指摘にする。

次の組も直さず、指摘のままにする。

- 見出しの中の組。空白を足す・取る直し方は、見出しのアンカーを変えうる
- 開きの `**` から閉じの `**` までに改行を含む組。修正の適用は箇所の始まりの行だけを対象行と比べるので、hookが対象行の外を書き換えることになる(ADR-0003)
- 内側に `*` がある組と、`*` が3つ以上続く並び。どの記号を組にするつもりかが決まらない
- `*` の並びが3つ以上あるブロックで、内側の端の空白だけが原因の組(`**a**と** b**です`)。同じ理由による

太字の前後の空白を削除する `ja-space-around-strong` と同時に有効にした設定は、不正にしない。ADR-0008が不正にするのは、修正が往復する組である。`ja-space-around-strong` は、空白を消した後も太字のままのときだけ空白を削除する。太字の修正が空白を入れるのは、空白が無いと太字にならない側だけなので、その空白は削除されず、往復しない。

利用者の置き換えの結果に太字の修正が当たる設定は、ほかの組み込みの修正ルールと同じく不正にする(ADR-0008)。`注意` を `**「注意」**` にする辞書では、太字の修正が結果を `「**注意**」` に変え、その中の `注意` に辞書がまた当たる。太字になるかは `**` の外側の文字で決まるので、この判定では、置き換えの結果が日本語の文の中に入るとみなす。捕捉参照には、太字になるかの判定でいちばん有利な中身を入れる。組の内側の参照は日本語の文字、組の外側で `**` に接する参照は空白とみなす。その中身でも修正が当たる組(`**「$1」**`、`$1**「注意」**`)は、参照が何であっても太字にならないので、不正にする。

## Considered Options

- 空白を足す直し方だけを、指摘のままにする。読者に見える空白を自動で増やさずに済む。句読点やコロンで終わる太字は、agentが手で直すことになる
- 修正ルールにせず、指摘の文面に直し方の案を出す。ADR-0009を変えずに済む。agentは、案を1件ずつ手で当てることになる
- `ja-space-around-strong` と同時に有効にした設定を、不正にする。往復を見込んで検討したが、実際には往復しないので、使える組み合わせを断るだけになる

## Consequences

- `yomiyasu-bold-not-rendered` を有効にしている利用者の `jafix fix` とhookが、本文を書き換えるようになる
- ADR-0009の3種類に当たらない修正ルールが、1つできる。今後の例外も、書き手の意図がはっきりしていることと、直した結果を機械的に確かめられることを条件にする
- 太字の修正の箇所は、開きの `**` から閉じの `**` までの1つである。内側にほかの修正ルールの箇所があると、重なりの規則(ADR-0013)で1回目は太字だけが直り、繰り返しの2回目に内側が直る
- 置き換えの結果に `**` を書いた辞書は、実際には空白の前でだけ使うものでも、設定の不正になることがある
- 太字の修正は、ほかの修正ルールと違い、固定の部分ごとではなく、固定の部分と参照をつないだ置き換えの結果の全体に当てる。捕捉参照をまたぐ組(`**「$1」**`)も判定に入る。組の外側で `**` に接する参照(`$1**「注意」**` の `$1`)を空白とみなすのは、空白の後の `**` は次が空白でなければ開きになれ、空白の前の `**` は前が空白でなければ閉じになれるからである。外側の参照を理由に組ごと判定から外すと、参照に接しない側の `**` が太字にならない置き換えを見逃す。ADR-0008の、参照に接する端の指摘を除く扱いは、ほかの修正ルールにだけ残る
- 参照の中身で太字になるかが変わる置き換えは、中身を推測せずに読み込む。実際の参照の中身によっては太字にならず、太字の修正と置き換えが互いの結果を書き換えて、修正を繰り返すと記号が増えることもある。`/(\s?)注意(\s?)/` を `$1**「注意」**$2` にする辞書では、`この注意を読む。` が1回目の修正で `この「**注意**」を読む。`、2回目で `この「****「注意」****」を読む。` になる。設定を読む時点では参照の中身を決められないので、リファレンスで、太字の修正を無効にするか、置き換えの結果が必ず太字になる形(`「**$1**」` など)に書くよう案内する
- Markdownの解析器が変わったら、確かめに使う解析の結果も変わるので、fixtureで直る組と直らない組を比べ直す
