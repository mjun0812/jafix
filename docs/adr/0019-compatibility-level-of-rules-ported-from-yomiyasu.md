# ADR-0019: yomiyasuから移したルールは判定の条件を写し、文書の種類による出し分けと件数の上限は移さない

yomiyasu 3.4.1のlintから移した組み込みのルールは、判定の条件(正規表現、語の一覧、除外の条件)を、文書の種類を指定しないときのyomiyasuから写す。期待値は、yomiyasu 3.4.1を例文にかけた実行結果から作り、その例文では指摘の出る行を一致させる。2026-11-27に、ダッシュや絵文字などの19の指摘ルールを足すときに決めた。

yomiyasuの仕組みのうち、次の3つは移さない。

- 文書の種類(`--doc-type`)によるルールの出し分け。jafixには文書の種類の指定が無いので、種類を指定しないyomiyasuと同じ判定を、すべての文書に当てる
- 利用者の語の一覧(`.yomiyasu-words/`)。指摘を外すには、`[filters]` の `allowlist` を使う
- 1文書あたりの件数の上限と点数。yomiyasuは、ダッシュの指摘を1文書に3件までにするなど、ルールごとに上限を持つ

本文の取り出し方と指摘の出し方には、jafixの仕組みを使う。yomiyasuはソースを行ごとに走査するが、jafixはMarkdownを解析して得た本文の範囲と、ほかのルールと同じ文の分割に判定を当てる。指摘は、文の単位のルールでは文ごとに文の先頭へ、語や記号を見るルールでは当たった語や記号ごとにその先頭へ出す。yomiyasuは、行ごとに1件を出す。

本文のうちどこを見るかは、ルールごとにyomiyasuの元のコードに合わせる。合わせるのは次の3点である。

- 見る行の種類。見出し・段落・リスト項目・表のセル・引用のどれに当てるかが、ルールごとに違う
- かぎ括弧や引用符の中を伏せるかどうか
- 直前の文の決め方。たとえば区切り線を挟んだとき、`yomiyasu-short-mochiron` は直前の文が無いものとして扱い、`yomiyasu-cleft-list-ending` は区切り線を越えて前の文を見る

絵文字は、yomiyasuの範囲の表を写さず、Unicodeの文字の性質で判定する。yomiyasuは、Unicode 18.0の絵文字の範囲をコードに固定している。jafixは、正規表現のEmojiの性質から数字・`#`・`*`・地域指示記号を除いた字を絵文字とみる。yomiyasuが絵文字とみる字は、単独でみる1,373字と、異体字セレクターが続くときだけみる36字である。この字で比べた結果、違いはUnicode 17と18で足された16字だけだった。

移す目的は、yomiyasuが見つける書き方をjafixでも見つけることである。出力を1件ずつ一致させることは目的にしない。textlintから移したルールでも、判定の条件を写し、jafixの本文と文の単位に当てている(ADR-0006)。

## Considered Options

- 文書の種類を指定する設定を足して、種類ごとの出し分けまで移す。設定と判定の分岐が増える。利用者は、この出し分けを求めていない
- yomiyasuの行ごとの走査と文の分割を、そのまま写す。同じ文書に対する本文の取り出し方を、ほかのルールと別にもう1つ持つことになる
- 絵文字の範囲の表を写す。表とUnicodeのライセンスの文書を持ち続け、Unicodeの版が上がるたびに表を作り直すことになる

## Consequences

- 例文に無い入力では、yomiyasuと指摘が変わりうる。行をまたぐ文は、行ではなく文の先頭に指摘が出る
- 本文の取り出し方で判定が変わる入力もある。インラインコードだけの項目の並びと、閉じの `#` がある見出しの直後の文がその例である
- 脚注の定義の本文にも当てる。yomiyasuは、脚注の定義の行を見ない
- yomiyasuがソースの行の記号を文字として読むことで生じる結果は、写さない。見出しの記号の後の文や、リンクの文字の先頭の語がその例である
- 1つの行に複数の語や記号があれば、jafixはyomiyasuより多くの指摘を出す
- yomiyasuの版が上がったら、例文の期待値を作り直して比べる
- yomiyasuから新しいルールを移すときは、見る行の種類・伏せる範囲・直前の文の決め方を、ルールごとに元のコードの実行結果で確かめる。共通の処理へ寄せるのは、その後にする
