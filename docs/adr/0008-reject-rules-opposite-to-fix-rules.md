# ADR-0008: 修正ルールと逆の書き方を求めるルールは、同時に有効にすると設定の誤りにする

jafixの修正ルールと逆の置き換えを求めるtextlintのルールも、組み込みに入れる。ただし、両方を同時に有効にした設定は、読み込みの時点で不正にし、どちらかを切るように理由で伝える。例は、`preset-jtf-style` の `4.3.1.丸かっこ（）` (日本語の隣の半角の丸括弧を全角にする)と、jafixの `fullwidth-paren` (全角の括弧を半角にする)である。

同時に有効なままだと、往復が止まらない。hookが括弧を半角に直すと、`4.3.1` がその半角を指摘する。agentが全角に戻すと、次の編集でhookがまた半角に直す。どちらのルールも、それだけなら正しく働くので、組み合わせを設定の時点で断るのが一番早く気付ける。

指摘ルール同士の食い違いは、この扱いの対象にしない。`！` を求めるルールと、`！` 自体を指摘する `no-exclamation-question-mark` がその例である。記号を使わない書き方で両方を満たせるので、往復にならない。

## Considered Options

- 逆の書き方を求めるルールを、組み込みに入れない。利用者の選べるルールが減る
- 入れて、衝突を避けるのは利用者に任せる。往復が起きてから気付くことになる

## Consequences

- 逆の書き方を求めるルールを入れるspecは、どの修正ルールと逆かを決め、同時に有効なときの設定の誤りの理由を足す。この判定の仕組みは、最初にそうしたルールを入れるspecで作る
- 修正ルールを足すときも、既にある組み込みのルールと逆でないかを確かめる
