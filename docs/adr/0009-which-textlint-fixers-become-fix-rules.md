# ADR-0009: textlintのfixerのうち、修正ルールにするのは字種・空白の削除・利用者が書いた置き換えだけにする

textlintでfixerを持つルールを移植するとき、jafixの修正ルール(hookがその場で書き換える)にするのは次の3種類である。

- 字種だけを変える置き換え。全角英数字を半角へ、康熙部首を同じ形の漢字へ、`･` を `・` へ変えるものなど
- 空白の削除
- 利用者が設定に書いた置き換え。prhの辞書と、置き換え付きのpattern

それ以外のfixerは、直さずに指摘する指摘ルールとする。次のものが、これに当たる。

- 組み込みの辞書による語の置き換え
- 空白や記号を足す置き換え
- 記号の種類を変える置き換え(`(` を `（` へ、`:` を `：` へ)

hookは、agentが今回変えた行を、確かめずにその場で書き換える。だから自動にするのは、文意に関わらない置き換えと、利用者が自分で決めた置き換えに限る。組み込みの辞書による語の置き換えは、固有名詞や識別子を別の語に書き換えることがある。たとえば `textlint-rule-spelling` は、候補が1つなら `textlint` を `texting` に直す。記号を足す・種類を変える置き換えは、文書ごとの表記の方針に関わるので、agentに判断させる。

1本目のspecでは、文字単位の置き換え4つ(NFD、半角カナ、ゼロ幅スペース、制御文字)だけを修正ルールにした。この決定はその基準を広げ、利用者が書いた置き換えを足したものである。

## Considered Options

- 1本目と同じく、字種と空白の削除だけを修正ルールにする。利用者が辞書で決めた置き換えも、直さずに指摘だけを出す
- fixerを持つルールを、すべて修正ルールにする。辞書による誤った書き換えが、確かめられないまま入る

## Consequences

- fixerを持つルールを入れるspecは、そのfixerが3種類のどれに当たるかを決める。当たらなければ指摘ルールにする
- `no-ai-emphasis-patterns` の見出しの太字を外す置き換えは、記号を外す置き換えなので、指摘ルールにした
