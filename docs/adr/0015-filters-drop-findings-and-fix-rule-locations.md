# ADR-0015: filterは `[filters]` に書き、指摘と修正ルールの箇所の両方を外す

textlintの2つのfilter(`textlint-filter-rule-comments` と `textlint-filter-rule-allowlist`)は、設定ファイルの `[builtin]` と並ぶ表 `[filters]` に、filterのID `comments`・`allowlist` をキーにして書く。値は `true`・`false`・オプションの表で、書かなければ無効である。filterが求めた外す範囲は、指摘ルールの指摘に加えて、組み込みの修正ルールの箇所と利用者の置き換えの箇所にも当てる。外した修正の箇所は、`jafix check` に出ず、`jafix fix` とhookが直さない。

置き場所を `[builtin]` と分けるのは、filterがルールではないからである。filterは指摘を出さず、ほかのルールの指摘と箇所を外す。textlintでも、`.textlintrc` の `rules` と別の `filters` に書く。`[builtin]` のキーはルールのIDかpresetの名前で、そこにfilterを混ぜると、組み込みのルールの数え方に、ルールでないものが入る。`comments` のような短い名前が、後でルールのIDと衝突することもありうる。設定の形は利用者との約束なので、2026-11-16に利用者が選んだ。

修正ルールの箇所にも当てるのは、コメントで囲んだ範囲を書き換えないことが、無効化を書く目的だからである。意図して規則に反する例(全角括弧や、日本語と英数字の間の空白)を `<!-- textlint-disable -->` で囲んでも、hookが直してしまえば囲む意味が無い。textlintの `--fix` も、filterの後に残った指摘のfixだけを当てる。

修正ルールの箇所は、重なりを解く前に外す。重なりを解いた後に外すと、IDを書いた無効化で外したルールの箇所が、同じ空白に当たる他のルールの箇所を先に捨てさせ、どちらも直らない。重なりの前に外せば、IDを書いた無効化は、そのルールだけを止める。また、組み込みの修正ルールは文字を消すか字種を変えるので、内容が変わればコメントとパターンの一致の位置も変わる。そのため、`jafix fix` とhookは、利用者の置き換えの前と、組み込みの修正ルールを当てる繰り返しの1回ごとに、その時点の内容から外す範囲を求め直す。

## Considered Options

- filterを `[builtin]` のキーにする。表は1つで済むが、組み込みのルールの数え方に、ルールでないものが入る
- 外す範囲を指摘だけに当て、修正ルールの箇所は直す。この案ではhookが囲んだ範囲の意図した書き方も書き換える
- 修正ルールの箇所を、重なりを解いた後に外す。IDを書いた無効化で、外したルールと重なる他のルールの箇所まで直らなくなる
- 外す範囲を最初の内容で1回だけ求める。修正後は位置がずれ、範囲が別の箇所を指す

## Consequences

- 外す範囲は文書の全体から求めるので、hookでは対象行の外にあるコメントとパターンの一致も、対象行の箇所を外す
- `ai-tech-writing-guideline` の件数の要約と、文書の全体で数えるルールは、外す前の数で指摘を決める。textlintと同じく、filterはルールの判定の後に働く
- 設定を書かない利用者の修正と指摘は変わらない(ADR-0007)
